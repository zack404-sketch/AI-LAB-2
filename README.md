# AI Lab 2 — Malware Detection on Windows PE Files

A machine-learning lab on **static malware detection**: classify Windows PE (Portable Executable) files as benign or malicious from pre-execution features, using a leakage-safe evaluation protocol, error forensics with SHAP, cost-based threshold selection, and a final CISO-style deployment recommendation.

> **Note:** the dataset is **synthetic** (EMBER-inspired, generated inside the notebook). Results illustrate the methodology and are not a claim about real-world detection performance.

## Dataset

Generated by `load_ember_forensic_dataset(n_samples=6000, seed=42)`:

- **6,000 files × 15 columns**, malware prevalence ≈ **26.8 %** (1,611 malware / 4,389 benign)
- Features include section entropy, import count, suspicious API imports, signature / RWX flags, virtual-to-raw size ratio, resource entropy, embedded URLs/IPs, compile timestamp anomaly, number of sections, TLS callback and export count
- Deliberate data traps: missing values, a parser sentinel value (`99999.0`), a **target-leakage column** (`VT_PostScan_Detections`), an ID column, a bimodal malware entropy pattern and ≈ 4 % noisy labels

## Lab structure

### Phase 0 — Environment and dataset
Imports, fixed seed (`42`), dataset generation.

### Phase 1 — Forensic data audit and problem formulation
- Class balance, missing values (`Import_Count`, `Resource_Entropy`), duplicates
- Detection of the `Virtual_to_Raw_Size_Ratio = 99999.0` sentinel (59 rows) → replaced by `NaN`
- **Leakage identified:** `VT_PostScan_Detections` (benign 0–2 vs malware 18–67) and the unique `SHA256_File_ID` are excluded
- Task definition: binary classification, positive class = malware; accuracy rejected in favour of F1, PR-AUC and cost

### Phase 2 — Leakage-safe evaluation protocol
- Stratified **80/20 split** (development set / lockbox test set)
- Pipelines with fold-safe median imputation (+ `RobustScaler` for linear models)
- **5-fold stratified CV** on 5 models: Logistic Regression, Decision Tree, Random Forest, LightGBM (or HistGradientBoosting fallback) and a Stacking ensemble
- Metrics: train/validation F1, overfitting gap, PR-AUC, fit time, inference latency

| Model | Val F1 | Val PR-AUC | Train–val gap |
|---|---|---|---|
| Stacking (LR+RF+Boost) | 0.924 | 0.908 | 0.036 |
| Logistic Regression | 0.924 | 0.908 | −0.001 |
| Random Forest | 0.924 | 0.905 | 0.076 |
| LightGBM | 0.922 | 0.903 | 0.076 |
| Decision Tree (deep) | 0.830 | 0.733 | 0.170 |

**Takeaways:** the deep tree overfits heavily; Random Forest fixes most of that variance; the linear baseline is fully competitive; boosting and stacking are not justified by their extra complexity.

### Phase 3 — Error forensics
- Find a verified test case where Logistic Regression misses malware that Random Forest catches
- **SHAP** analysis (global beeswarm and bar plot, local waterfall, dependence plot)
- Most influential features overall: `Export_Count`, `Virtual_to_Raw_Size_Ratio`, `Num_Embedded_URLs_IPs`, `Suspicious_API_Imports`, `Num_Sections`
- Discussion of why SHAP is **not** causal and why the synthetic data limits what can be concluded

### Phase 4 — Cost-based threshold selection
- Costs: **FP = $25** (triage) or **$2,000** (blocking), **FN = $500**
- Thresholds chosen on development out-of-fold predictions only, **frozen**, then evaluated once on the lockbox
- Triage result for Logistic Regression: threshold 0.28, 10 FP, 34 FN, precision 0.966, recall 0.894, cost $17,250
- Capacity check: ≈ 25 % of files flagged → far above a 120-alert/day target at 12,000 files/day

### Phase 5 — Final architecture decision (CISO recommendation)
- **Recommended model:** Logistic Regression, with Random Forest kept as a shadow challenger
- **Deployment mode:** analyst-assisted triage; **no automatic blocking** for now
- Documented risks: synthetic-to-real gap, label noise, prevalence shift, drift, calibration, adversarial adaptation, analyst workload, monitoring and retraining


## Limitations

- Synthetic data with 27 % malware prevalence, far above a realistic submission stream
- Cost values ($25 / $500 / $2,000) are illustrative planning numbers
- Probabilities are uncalibrated; latency figures come from a shared 2-core sandbox and are indicative only
